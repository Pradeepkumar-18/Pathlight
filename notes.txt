How each part adapts
Need	Mechanism	Effect
Know where the project is	SessionStart hook reads progress.md and prints about 10 lines (phase, current task, blockers, next step)	Every session starts with up-to-date state, without reading the whole file
Rules that fit the code being edited	paths: frontmatter in .claude/rules/*.md	UI rules never load during agent work, and the other way round
Personal vs team preferences	~/.claude/ (you, all projects) → .claude/settings.json (team) → settings.local.json + CLAUDE.local.md (you, this project)	Each person adjusts their own setup without changing the shared files
Learning from your corrections	Auto memory, plus a line in CLAUDE.md: "when corrected, propose a rule update"	The rules grow from real mistakes
Enforcing "ask before changing"	PreToolUse hook that exits with code 2 on schema, migration or .env paths	Claude can't skip the rule, and it costs no tokens to remind it
Token optimisation, ordered by impact
Your specs are the biggest cost. Each is 27–38 KB, roughly 8–10k tokens. Never @import them into CLAUDE.md. Send spec questions through the spec-reader subagent: its reading happens in its own context window, and only the answer comes back.
Slim down CLAUDE.md. It's about 8.6 KB now and loads on every turn. Keep the summary, repo map, commands and hard rules there. Move the UI, agent, DB and testing conventions into path-scoped rules.
Pick models by task. Use Sonnet for normal coding, Opus for planning and checkpoints (or the opusplan alias), and Haiku for spec-reader and test-runner.
Let a subagent run the tests. pnpm output is long and noisy. test-runner returns only the failures.
Prefer skills over long rules. Only a skill's one-line description is always loaded; the body loads when you run it. Put disable-model-invocation: true on /start-task and /finish-task so they run only when you call them.
Clear between tasks. Your "one task per session" rule fits this: run /clear after /finish-task, and the SessionStart hook sets up the next session.
Keep MCP servers to a minimum. Each connected server adds tool definitions.
Use permission allowlists. Allowing pnpm lint, typecheck, test:*, git status and git diff cuts prompts and back-and-forth. Denying Read on .env, *.db and node_modules/** stops accidental large or sensitive reads.
